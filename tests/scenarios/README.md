# Scenarios

Generated by `docs/code_map.py` from each scenario's docstring; do not edit by hand. Every scenario has a folder with the test and a README that draws what happens and lists what is checked. `bazel test //tests/scenarios:all` runs them; the ones tagged slow wait out real heartbeat intervals.

- [Any vs all](any_vs_all/README.md): whom: ALL reaches every backend, whom: ANY reaches exactly one.
- [Backend dies](backend_dies/README.md): one of two backends crashes mid-run; the survivor takes over.
- [Backend drains](backend_drains/README.md): a backend asked to leave drains: it declines searches, serves what arrives, then exits.
- [Backend drains until done](backend_drains_until_done/README.md): a backend decides for itself when its drain is over, by overriding drained().
- [Backend raises](backend_raises/README.md): a backend whose handler throws answers with BACKEND_ERROR, at once, and keeps serving.
- [Concurrent clients](concurrent_clients/README.md): several clients query one backend at the same time without cross-talk.
- [Connected peers](connected_peers/README.md): the multiplexer's peers file lists who is connected, rewritten on every change.
- [Direct addressing](direct_addressing/README.md): a message with `to` set reaches only that instance, whatever the rules say.
- [Direct queue full](direct_queue_full/README.md): a directly addressed message dropped for a full queue is reported as a delivery error.
- [Event all backends](event_all_backends/README.md): a client's events reach every event backend (whom: ALL).
- [Hostile input](hostile_input/README.md): malformed and out-of-order input must cost the peer its connection, never the multiplexer.
- [Idle client](idle_client/README.md): a passive client idles past both drop intervals and still works.
- [Idle cpu](idle_cpu/README.md): an idle deployment uses no CPU: every wait loop sleeps, none spins.
- [Label role](label_role/README.md): a binary named by its label plays the backend role next to the shipped client.
- [Large payload](large_payload/README.md): a 16 MiB query and its echo make the round trip intact.
- [Mx hangs](mx_hangs/README.md): one of two multiplexers hangs without closing its sockets; queries survive, some slowly.
- [Mx restarts](mx_restarts/README.md): the multiplexer restarts under a live backend and a passive client; nobody notices.
- [Mx restarts under events](mx_restarts_under_events/README.md): the multiplexer restarts between two events; a flushing sender loses none of its calls.
- [Mx restarts under idle client](mx_restarts_under_idle_client/README.md): the multiplexer restarts while a passive client is idle; its next call still works.
- [Query one](query_one/README.md): one multiplexer, one backend, one client, one query.
- [Raw protocol](raw_protocol/README.md): a peer speaking the wire format directly, without the client library.
- [Recording](recording/README.md): the multiplexer records every peer event and delivery attempt, and the recording reads back.
- [Recording latency](recording_latency/README.md): recording costs the routed message nothing a client can measure.
- [Recording tap](recording_tap/README.md): a peer taps two multiplexers and receives every record live, tagged with the multiplexer that routed it; a slow tap loses records but nothing else.
- [Remote recording](remote_recording/README.md): a recording session is started and stopped on two multiplexers over the protocol, one file each in a shared directory.
- [Remote recording cap](remote_recording_cap/README.md): a remote session closes itself at its byte cap or its time cap, and a session started with --record can be stopped remotely.
- [Remote recording refused](remote_recording_refused/README.md): every way a recording request is refused: the feature off, a bad label, a second session, and a stop with nothing to stop.
- [Remote recording stay](remote_recording_stay/README.md): a session kept by `mxcontrol recording start --stay` follows a replica through a restart and ends on SIGINT.
- [Rolling restart](rolling_restart/README.md): three multiplexers restarted one after another under traffic; nobody notices.
- [Round robin](round_robin/README.md): two backends of one type share the queries of one client.
- [Server lifecycle](server_lifecycle/README.md): the server reports the port it bound and exits cleanly on SIGTERM.
- [Soak memory](soak_memory/README.md): thousands of queries do not make the multiplexer, the backend or the client grow.
- [Threaded backend dies](threaded_backend_dies/README.md): a ThreadedClient with many queries in flight when one of two backends crashes.
- [Threaded idle](threaded_idle/README.md): a ThreadedClient of an active peer type idles past the drop intervals and still works.
- [Threaded mx restarts](threaded_mx_restarts/README.md): the multiplexer restarts with a ThreadedClient's queries in flight; all are answered.
- [Threaded queries](threaded_queries/README.md): a ThreadedClient answers queries one at a time and many at once, on the full mesh.
- [Threaded workers](threaded_workers/README.md): worker threads share one ThreadedClient; each gets its replies through its own queue.
- [Two mx backend on one](two_mx_backend_on_one/README.md): two multiplexers, the backend behind only one; the client finds it.
- [Two mx backends on each](two_mx_backends_on_each/README.md): two multiplexers with a backend behind each; a client on both.
- [Two request types](two_request_types/README.md): two request types are routed to their own backend types.
- [Unrouted type](unrouted_type/README.md): a query of a type with no routing rule fails at once, not after a timeout.
